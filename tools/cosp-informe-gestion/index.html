Certeza

Cómo se garantiza la información

La certeza no sale de una sola planilla. Cada hora tiene que coincidir en tres preguntas: qué se vendió, qué se planificó y qué se fichó. LOL cierra el cuarto: qué se paga.

FuentePregunta que respondeRol en el cruce
Excel de cronogramasQué se planificóFuente histórica de la malla; se está migrando a COSP
SLA COSPQué se vendióServicio por puesto/banda; no se inventa la hora
Plan COSPQué se asignóTurnos con códigos CCT (M/T/N/D12/N12/RET/F/FT)
MarcacionesQué se fichóHoras reales; desvío vs plan; warnings si falta marca
LOLQué se liquidó / legajoCruce de certeza hoy; destino de la API de haberes

Qué ya no se discute

El modelo es CCT 422/05: códigos M/T/N/D12/N12, RET/F/FT, descanso 10 h, techo 192/200, ciclo 26→25, nocturnidad 21–06.

Prefactura y reportes leen la misma hora facturable. Análisis usa el extracto mensual (hours_balances) y la malla.

La API de liquidación ya está especificada: horas plan/real, diurnas/nocturnas, FT al 100 %, plus feriado, bolsa 200, novedades RRHH y warnings de fichada faltante.

Qué todavía es trabajo de carga

Sistemas está ingresando cronogramas desde el 10/08. Julio no es un mes limpio de punta a punta en todos los objetivos.

Agosto se cierra en los próximos 10 días. Hasta ahí, la prefactura refleja el avance de carga, no un cierre contable.

LOL sigue siendo cruce manual / de contralor. El inserto de API (liquidación + novedades) tiene presupuesto pedido; no está desarrollado del lado de ellos.

Haberes

LOL — liquidación y novedades

COSP ya publica el contrato que LOL tiene que consumir (payrollApi): ciclo 26→25, una fila por empleado, horas teóricas y reales, diurnas/nocturnas, FT al 100 %, plus feriado, bolsa 200 (simples / 50 %), novedades RRHH y warnings. El modo planificado vs fichado lo define COSP, no LOL. Ya se pidió presupuesto a LOL para el inserto de esa API (liquidaciones + novedades).

La decisión que más asusta y menos debería

"¿Dónde subo esto?" es la pregunta que paraliza a más emprendedores de los que debería. La respuesta incorrecta es buscar la solución perfecta antes de tener un usuario real.

Qué significa "subir" tu SaaS

Para que el mundo pueda acceder, necesitás que tu aplicación viva en una computadora siempre conectada a internet — un servidor en la nube.

Las plataformas para empezar

Firebase de Google

La plataforma que elegí para COSP. Incluye Firestore, Firebase Authentication, Firebase Storage, Cloud Functions y Firebase Hosting. El plan Spark es generoso para proyectos pequeños; Blaze escala linealmente con el uso.

Vercel

La mejor opción para el frontend con React, Next.js o Vue. Conectás tu repositorio de GitHub y se despliega automáticamente. Plan gratuito generoso.

Railway y Render

Para backend tradicional con Node.js, Python o Ruby. Planes gratuitos con limitaciones y planes pagos razonables.

Las plataformas para cuando escalás

  • DigitalOcean: servidores virtuales desde seis dólares mensuales. Paso natural cuando el proyecto crece.
  • AWS, Google Cloud, Azure: escala enterprise. No empieces acá — la complejidad no está justificada hasta que tenés escala real y equipo técnico.

La decisión de infraestructura en COSP

Firebase priorizó tres cosas: seguridad de los datos, disponibilidad del sistema y escalabilidad sin gestión operativa continua. En un entorno corporativo con datos de personal operativo, la infraestructura no puede fallar.

El dominio y el SSL

Dominio: la dirección de tu SaaS en internet (tuproducto.com). Cuesta entre diez y quince dólares anuales.

SSL: el protocolo que cifra la comunicación y muestra el candado en el navegador. Nunca lances una SaaS sin SSL. Todos los servicios de hosting mencionados lo incluyen gratis.
